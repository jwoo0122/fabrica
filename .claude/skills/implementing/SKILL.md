# 요구사항 구현과 처리

지금부터 제공받은 계획에 맞춰 작업을 진행한다.

## 순서

### 검증 정리와 구현

검증 수단은 모두 결정론적 구조를 가져야 한다.

#### 장기 하네스 정리

1. 검증 수단 중 장기 하네스로 프로젝트에 삽입하는 것이 흑자인 것들은 직접 구현한다.
2. 구현 후 /codex:review로 검사를 받는다. 지적 사항은 자동으로 반영한다.
3. 실제 하네스가 통과하는지 확인한다. 구현 이전 단계이므로 통과할 수 없어야 한다.

### 계획 정립

#### 단계별 정리

1. 필요하다면, regression을 방지하기 위해 구현의 단계를 세부화한다. 후퇴하지 않는 최소 검증 지점을 단계적으로 세워서 결과물이 목표를 향해 꾸준히 진전하게 만든다.

#### 하네스 구축과 구현

1. /codex:rescue 스킬을 활용하여, plan 중 검증 수단 구현 관련을 모두 일임한다. 이 작업은 background로 처리한다.
2. 요구사항을 단계적으로 구현한다.
3. 앞선 단계에서 구축한 모든 검증 수단을 동원하여 구현 결과를 확인한다. 결과가 모두 통과할 때까지 작업을 이어간다.

### 최종 제출

1. 최종 구현된 내용과 검증 수단 결과가 최초 요구사항 문서의 내용과 정렬되어 있는지 검토한다.
2. /codex:adversarial-review를 통해 같은 검토를 한 번 더 진행한다.
3. 검토 결과를 사용자에게 제출한다.
