# 브레인 스토밍과 하네스 정립

지금부터 요구사항을 분석하고, 하네스를 정립한다.
이 스킬은 Plan Mode에서 사용된다.

## 순서

### 계획과 피드백

1. (사용자와 상호작용) 인자로 받은 요구사항의 목표를 이해한다. 요구사항은 모호하며 자연어로 두루뭉술하게 기술되어 있으므로, 이를 정확하고 논리적으로 모순없는 논증 체계로 정리하는 정제 과정이 필요하다. 따라서, 이 이해가 완전해질 때까지 사용자의 의도를 지속적으로 묻는다. 이때 필요하다면 AskUserQuestion를 활용한다.

2. (혼자 작업) 완벽하게 사용자의 의도를 이해한 후, 이를 검증하기 위한 검증 수단 체계를 마련한다. 이는 agent-browser, claude-in-chrome, 테스트 스위트, 네이티브 스크립트(AppleScript) 등 시스템에서 활용 가능한 모든 검증 수단을 극단적으로 활용한 체계이다. 이 체계는 재사용 가능한 형태로 장기 보존 가능한 것과, 현재 작업 내용에 최적화된 일회성 수단으로 구분한다.  적절할 경우, 검증용 스킬을 구성하여 직접 프로젝트에 삽입하여 추후 작업 맥락에 맞춰 자연스럽게 호출할 수 있는 수단으로 장기보존한다. 이 단계에서는 검증 수단의 전체적인 설계도만 갖춘다.

3. (혼자 작업) 정립된 하네스 설계를 codex에게 넘긴다. 이때 /codex:adversarial-review 스킬을 호출하여 리뷰를 요구한다. 해당 스킬의 사용법은 스킬 문서를 참고한다. codex로부터 받은 리뷰 사항을 설계에 반영하여 PR의 목표 범위와 검증 수단을 정리한다.

4. (사용자와 상호작용) 간결하고 정제된 설명으로 사용자에게 최종 확인을 받는다. 피드백이 있다면 수용하고 2번으로 돌아간다.

5. 구체적인 계획이 정리되면 Plan Mode 종료 후 작업 돌입을 제안한다. 이때 본 Planning 스킬이 사용되었음을 기록에 반드시 남긴다.
